# Data authority and versioned interfaces

| Data or interface | Owner and contract |
| --- | --- |
| Playthrough and actor | Save lifecycle + native resolver for identity and observations, PostgreSQL for the binding and version history. Use stable source/plugin-local identity and actor reference/incarnation. Do not key by display name or unresolved load-order index. Scope first save, load, save branches and retired identities explicitly. |
| World events | Engine, authored sources or named observation producer own evidence. The SQL event ledger admits idempotent, sourced records with occurrence game time, ingestion timestamp, playthrough, subject, audience and origin. Late and corrected observations retain distinct lineage. |
| Mind, relationships and history | Actor-scoped relational records with transaction-owned updates. Authored defaults, personal state and perceptions have separate sources and revision keys. Mark observed relationships, subjective judgments and alleged changes distinctly. |
| Knowledge provenance | Oghma supplies attributable authored/corpus material in its license and time scope. Dynamic Oghma ingests eligible witnessed material under its own evidence path. Existing CHIM memory participates through scoped records linked to delivery or approved observations. Ground facts, rumors, belief, uncertainty, private data and contradictory accounts distinctly. Check eligibility before ranking and before prompt admission. |
| Decision request/result | Scheduler owns correlation, input snapshot, permissions, context limit and deadline. A provider returns a proposal and diagnostics. Only the action adapter can admit a supported effect. |
| Action and speech | Engine adapter owns physical receipts. Native delivery owns observed playback receipts; synthesis availability and generated text are earlier stages. Persist conversation claims only from eligible delivery, explicit perception and correction events. |
| Search, readable mind views and prompts | Rebuildable from authoritative versioned rows with scoped provenance. MDKV-style readable views can aid inspection, replay and prompt building. Never use a derived cache to bypass visibility or revive an erased/invalidated record. |
| Install and release manifests | Skyforge owns install manifest/lock mechanics. Collection owns curated pins and compatibility. Release manifest joins Core revision/artifacts, Collection revision/pins, dependency/profile/schema identity, evidence and rollback. |
| Telemetry | Producing component owns event metadata. Diagnostics can correlate opaque identifiers across components without recording sensitive payloads. |

For the initial PostgreSQL design, use playthrough-qualified unique keys for entity and event identities, indexes aligned with actor/audience and game-time reads, and transactional admission of one event and its owned state updates. Store engine-bound work in a pending state until an attributable receipt is reconciled. Replays must be harmless even after save/load or a process crash. Scope each query before ranking across shared storage. Plan retention, corrections and authorized rebuilds for both SQL and descendants. Verify indexed query plans and projection rebuilds with synthetic data and volumes that represent actor and event growth.

Contracts name the producer, consumer, authority, compatibility policy and validation point. Identify wire schemas by name and major version. Reject unknown major versions at ingress; agree on additive compatibility and explicit reader support before introducing minor variants. Version SQL migrations independently of the event schema. Test fresh install, legacy data, restore, replay and rollback or forward repair on a disposable PostgreSQL instance matching the intended extension versions. Keep compatibility readers during staged rollout and record when removal is safe. Never apply a foundation fixture or proposed schema to a live playthrough.

The [fixture contracts](../../contracts/README.md) establish a narrow evidence envelope and receipt shape for future adapter work. They do not replace existing native or backend wire formats.
