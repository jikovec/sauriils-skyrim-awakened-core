# Architecture decision records

The LW-ADR identifiers carry forward the 23 November living-world decisions. The private reconciliation is historical provenance. Amend the maintained decision here with its owning Issue and a clear supersession trail. Accepted architecture describes the required boundary. Implementation and qualification evidence belong to the owning Issue.

| ID | Decision and rationale | Alternatives and consequences | Implementation status and work |
| --- | --- | --- | --- |
| LW-ADR-01 | A persistent mind is keyed to playthrough, effective actor reference and incarnation. Several instances can share authored base inputs while acquiring different lives. | Display-name or base-only keys can collide. Stable engine identity, branch policy and explicit retirement/reconciliation are required. | Required. Candidate guards exist. The [identity fixture contract](../../contracts/README.md#identity-version-1) defines the key and has no producer yet; whole-lifecycle validation pending. [Identity](https://github.com/jikovec/sauriils-skyrim-awakened-core/issues/58), [mind lifecycle](https://github.com/jikovec/sauriils-skyrim-awakened-core/issues/65). |
| LW-ADR-02 | Skyrim owns physical and authored outcomes. PostgreSQL owns admitted cross-session facts and mind state. Rebuild search and readable projections from that authority. | A second writable mind store creates divergence. An engine effect and SQL transaction need reconciliation and replay-safe identities. | Required. Existing CHIM SQL and native boundaries need versioned adapters. [World authority](https://github.com/jikovec/sauriils-skyrim-awakened-core/issues/35), [events](https://github.com/jikovec/sauriils-skyrim-awakened-core/issues/61). |
| LW-ADR-03 | Keep lore provenance, observed world facts and actor beliefs distinct. Scope retrieval to the actor and eligible audience before ranking and again before context admission. | A global truth prompt leaks secrets and flattens disputed lore. Scoped retrieval, correction lineage and time-aware queries require negative tests. | Required. CHIM/Oghma paths exist; end-to-end audience and belief policy pending. [Lore verification](https://github.com/jikovec/sauriils-skyrim-awakened-core/issues/42), [propagation](https://github.com/jikovec/sauriils-skyrim-awakened-core/issues/62). |
| LW-ADR-04 | Use deterministic constraints, lightweight decisions, shared local inference and bounded scheduling. Admit work under measured gameplay budgets. | Resident models for all actors or unrestricted background reasoning crowd out the game. Queue limits, stale cancellation and fair deferred service become explicit policy. | Required target. Existing services support local inference; resource and scheduler qualification pending. [Allocation](https://github.com/jikovec/sauriils-skyrim-awakened-core/issues/9), [admission](https://github.com/jikovec/sauriils-skyrim-awakened-core/issues/55), [scheduling](https://github.com/jikovec/sauriils-skyrim-awakened-core/issues/64). |
| LW-ADR-05 | Use typed proposals and attributable engine/playback receipts for physical effects and delivered speech. Preserve authored scenes and protect claims through interruption, reload and cancellation. | Inferring completion from generated language or a timeout creates false history. Bounded actions need eligibility, receipts and reconciliation. | Required target. Verify one adapter/effect and one delivered speech path at a time. [Actions](https://github.com/jikovec/sauriils-skyrim-awakened-core/issues/48), [delivered audio](https://github.com/jikovec/sauriils-skyrim-awakened-core/issues/39). |
| LW-ADR-06 | Gate narrative changes and release readiness on authored compatibility and representative, longitudinal evidence. | Startup-only or isolated demonstrations omit save, quest, world and perception failures. Keep exact runnable identities and repeatable scenarios. | Required. [Narrative origins](https://github.com/jikovec/sauriils-skyrim-awakened-core/issues/50), [Collection qualification](https://github.com/jikovec/sauriils-skyrim-awakened/issues/4). |
| ENG-ADR-01 | Core maintains shared architecture and source contracts. Collection integrates cleared Core revisions and owns playable reference compatibility. The owner workspace stays outside Git. | A combined runtime checkout would mix licensing, personal data and validation levels. Source promotion requires explicit path selection and rights review. | Implemented as repository orientation and review workflow. Native and backend source remain individually gated by [Core rights](https://github.com/jikovec/sauriils-skyrim-awakened-core/issues/6). |
| ENG-ADR-02 | Run public source checks on ordinary hosted Linux and keep private runtime qualification on owner-authorized isolated rigs. | Self-hosted CI or a full game fixture would expose private assets and create a second deployment path. Real integration remains a separate evidence lane. | Source verification entrypoints and workflow defined here. Fresh installer qualification remains [Core portability](https://github.com/jikovec/sauriils-skyrim-awakened-core/issues/7). |
| ENG-ADR-03 | Introduce closed, versioned fixture contracts at observable boundaries before adopting wire changes. | A rewrite of CHIM or a universal schema would destabilize working paths. Migration requires per-producer evidence and readers that declare supported versions. | Source JSON schemas and negative fixtures cover evidence metadata, receipt states and identity resolution. Proposed mind payloads and every producer adoption need owner-specific implementation under the existing Issues above. |
| ENG-ADR-04 | Each `main` ruleset requires its one source check from GitHub Actions on a pull request that contains the current `main`, and the check itself verifies the workflow against a reviewed policy. | Optional checks let failing dependency updates reach `main` on 24 November. A second maintainer or required approvals would block the only owner. A renamed job needs an owner ruleset step. | Enforced and qualified on both repositories. [Required checks](https://github.com/jikovec/sauriils-skyrim-awakened-core/issues/173), [hosted controls](../engineering/hosted-controls.md). |
| ENG-ADR-05 | Skyforge admits an archive before installing it: it binds the approved digest to the open file the extractor reads, confines and bounds the extractor, inspects the staged tree, allows executable content only by declared class and exchanges mod folders atomically. Every decision leaves a versioned receipt. | Checking a digest at download time only, or trusting each extractor's own path handling, leaves a substitution window and depends on tool behaviour. Kernel confinement needs Landlock. Existing manifests must declare executable classes before reinstalling such entries. | Implemented in the public source with synthetic negative fixtures. Adoption in a private installer build and its manifests is a separate owner step. [Admission](https://github.com/jikovec/sauriils-skyrim-awakened-core/issues/168), [design](../engineering/archive-admission.md). |
